# P0 #3 prompt 強化 + loop サイレント終了フォールバック

[./2026-05-21_07-p0-3-recovery-loop.md](./2026-05-21_07-p0-3-recovery-loop.md) で言及した強化待ちアイテムに対応。

## 今回の実装内容

### 1. _TESTER_ROLE / _AUDITOR_ROLE prompt 表現調整

**問題**：旧 prompt では「task_complete 明示的終了」をテンプレートの末尾に配置し、かつ「サイレント終了 = デフォルト成功」と記述していた――
実際の LLM 動作では非常に簡単にサイレント終了してしまい、明示的プロトコルがもたらす観測可能性（success / summary）を失っている。

**対応方法**：
- 【終了要件 - 必読】ブロックを prompt の最上部に移動し、「**必須**」を強調
- 成功 + 放棄の 2 つの few-shot 例を追加
- 「サイレント終了 = デフォルト成功」のような逆向きのシグナルを削除
- tools_schema.py の task_complete description も同期更新

### 2. fix() / audit() サイレント終了フォールバック

**設計**：この一巡で LLM がツールを呼び出さなかった場合――

- 旧動作：直接 return（完了と見なす）
- 新動作：`silent_prompted == False` の場合、system メッセージを注入して 1 度だけ再質問（「プロトコル上必ず task_complete を...」）、`silent_prompted = True` を設定、ループ継続
- 2 回目のサイレント → 実終了（無限追問スパムを回避）

1 回だけフォールバック実施――最悪の場合 1 ラウンド余分に消費するが、直接サイレント終了して終了シグナルを失うより価値がある。

### 3. _CODER_ROLE テンプレート 4 スコープ制御：linter の責務明確化

**問題**：テンプレート 4 では既に「失敗事例が必ずしも今回の追加ではない」と説明されていたが、pytest 失敗に限定されていた。
ruff/flake8/pyright が報告する未使用インポート（F401）、未使用変数など、LLM は便利に修正しようとする――
しかし這らの多くは**今回の plan ファイル範囲に含まれていない**、事前存在していたノイズだ。

**対応方法**：テンプレート 4 に 1 文追加：linter エラーが今回の plan ファイル範囲外の場合、事前存在問題として扱い、記録するが修正しない。

## 検証

`python tests/run_unit.py` → 9/9 ファイルパス、新規失敗なし。

## 影響ファイル

- agent.py：_TESTER_ROLE / _AUDITOR_ROLE / _CODER_ROLE テンプレート 4 / fix() / audit()
- tools_schema.py：task_complete description

## 評価

prompt 表現 + loop フォールバックは相補的――prompt 改だけでも LLM は時々サイレント終了；フォールバックだけだと明示的プロトコルなしで LLM は task_complete を主動的に実行しない。両者を組み合わせてはじめて閉じたループになる。

linter 責務ルールは範囲制御原則を「テスト次元」から「lint 次元」に拡張し、タスク漂移で技術債クリーンアップに吸収されるのを回避する。
