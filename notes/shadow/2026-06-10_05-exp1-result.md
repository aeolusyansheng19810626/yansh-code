# 实验1 结果：逼 agent 留测试（role vs gate 对照）（2026-06-10）

> 代码见分支 exp/solo-test-enforcement（commit 1aad42f）。三组全 sonnet 干净 ws，单次。
> A=longrun-miniql-exp1-role，B=longrun-miniql-exp1-gate，baseline=R19/R20/R21。

## 结果

| 组 | 强制方式 | 建 tests/ | smoke | 黑盒 | gate 裁定 | success | 成本/耗时 |
|---|---|---|---|---|---|---|---|
| baseline R20/R21 | off | 不建（只写根目录 _test_*.py 草稿） | 无 | 10/10、9/10 | no_command / failed | false | ~$13 |
| A：role 提示词（概率） | _SOLO_ROLE 追加「测试优先」强硬段 | 全套5个(lexer/parser/analyzer/executor) | **有 test_smoke.py** | 10/10 | **passed** | false* | $13.19 / 887s |
| B：gate 硬卡（确定性） | collected-0+有实现→强制回灌 | 部分(lexer/parser) | 无 | 10/10 | failed | false | $13.46 / 492s |

\* A 组兜底裁定 passed，但 final_success=agent_completed AND passed；烧满 120 轮时 agent_completed=False（未重宣告）→ success 仍 false。

## 发现

1. **role（A）单次表现最好**：建全套测试 + smoke，gate 首次 passed。原假设「提示词大概率漏」被这次推翻——它照做了。
2. **但这正是「概率」**：单次命中 ≠ 保证。role 的价值要多次跑看方差（有时全套、有时漏），单次不能定论 role>gate。
3. **gate（B）假性失效，暴露设计漏洞**：agent 随手建 test_lexer/test_parser → collected>0 → 硬卡（只卡 collected-0）被绕过，强制回灌触发 0 次。但 executor/HAVING 等核心没测。**「有测试」≠「测了关键能力」，硬卡卡错判据。**
4. **强化「hook 确定性」但加一条前提**：硬卡的确定性取决于判据设对。gate 没拦住不是硬卡无效，是卡点设在「有没有任意测试」这个太易满足的地方。该卡「有没有端到端 smoke」——smoke 测关键调用链，随手单测糊弄不过去。
5. **三组都烧满 120 轮**：harness 效率短板与强制策略无关，稳定复现。
6. **附带发现：兜底+agent_completed 判定遗留缺口**——兜底裁定 passed 时，若 agent 因烧满轮次未重宣告（agent_completed=False），final_success 仍 false。R19 兜底时未覆盖此交互。可考虑：兜底裁定 passed 时一并认可完成（曾 task_complete 过 + 测试绿）。

## 下一步：解法B v2（合并 #6 与硬卡）

gate 硬卡判据从「collected-0（无任意测试）」升级为「**有实现入口（__main__.py/cli.py）却无 tests/test_smoke.py → 强制回灌补 smoke**」。理由：smoke 是端到端的，糊弄不过去；单测可测无关痛痒的东西绕过 collected-0。这把 #6（原只在 passed 分支检查 no_smoke）下沉为主动硬卡。

可选并做发现6 的兜底判定修正。

## 方法论备注（Workflow 教训）

首次用 Workflow 并行 spawn 两个 subagent 跑长任务（各 15min）失败：subagent 启动后台 yansh 后，自己 loop 提前结束，没等到完成 → 返回 null。**Workflow 适合「subagent 自己干活并返回」，不适合「看管比自身生命周期更长的外部进程」**。改用主线程后台任务（自己等完成通知）可靠。下次：Workflow 管编排/并行 fan-out，长任务执行+等待放主线程。
