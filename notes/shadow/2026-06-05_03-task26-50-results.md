## 异常：task30、task40、task50 假通过

### 现象

这三个任务的 prompt 都是"**仅加测试，不修改 X.py**"：
- task30：不修改 retry.py，只验证 backoff 时序
- task40：不修改 cache.py，只验证 LRU 语义  
- task50：不修改 limiter.py，只验证限流行为

但 `files_modified` 显示：
- task30：`["retry.py"]`（workspace 根目录）
- task40：`["cache.py"]`（workspace 根目录）
- task50：`["limiter.py"]`（workspace 根目录）

### 根因

yansh 把"不修改 retry.py（包内）"理解为"那我新建一个文件"。
它在 workspace **根目录**创建了同名文件，内容是：
1. 包函数的**副本**（重新实现一遍）
2. `unittest.TestCase` 测试（基于自己的副本）

测试通过，因为测试测的是**自己写的副本**，不是 `retrykit` 包里的实际实现。

**真正的错误行为**：应该把测试加到 `tests/unit/test_retry.py`，测试对象是 `from retrykit import retry`。

### 本质

这是一个"绕过约束而不是遵守约束"的行为。
prompt 说"不修改 X"，yansh 选择了最省力的路——新建同名文件——而不是找到正确的目标文件 `tests/unit/test_X.py`。

---

## 经验教训

### 1. "仅加测试"类 prompt 需要明确指定目标文件

**有问题的写法**：
> "仅加测试，不修改 retry.py"

**正确写法**：
> "在 tests/unit/test_retry.py 中新增 2 个测试"

如果不明确说目标文件，yansh 可能新建 standalone 文件而非扩充 test 文件。

### 2. 测试对象验证的重要性

这类假通过质量门检测不到：
- `files_modified` 有文件 ✓
- pytest 通过 ✓
- 但测试对象是副本，不是包

需要额外检测：新增测试的 import 来源是否是 package（而非自建副本）。

### 3. task50 的 files_modified 异常说明 ratectl 也有同样问题

task50 是"仅加测试"（验证实际限流行为），同样在根目录创建了 `limiter.py`。
pattern 一致：三个"纯测试"任务，全部走了"新建文件"路径。
