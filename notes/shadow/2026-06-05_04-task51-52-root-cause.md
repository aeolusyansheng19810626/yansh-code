# task51/52 根因分析

## task51（只读探索，runner 判 success=true，实际错误）

**任务**：找 `_dispatch_tool_calls` 函数并发/串行触发条件，**不要修改任何代码**。

**实际行为**：yansh 修改了 agent.py（删除 3 个"未用导入"：`get_model_price`、`dispatch_subagent`、`get_latest_snapshot`），`files_modified=["agent.py"]`。

**root cause**：
- yansh 把"不要修改任何代码"当成 soft hint，仍进入 code 模式写文件
- runner 判据只校验"无新增测试失败"，对只读任务没有断言 `files_modified==[]`

**修复方向**：
- runner：只读任务断言 `files_modified==[]`，非空即 fail
- yansh：识别"只读/探索"信号，禁用写工具

## task52（`case_sensitive` 参数，files=[]，空实现 exit 0）

**任务**：给 `search_in_files` 加 `case_sensitive=True` 参数 + 2 个单测。

**实际行为**：`files_modified=[]`，三个计划文件（tools.py / tools_schema.py / test_tools.py）全部未修改。

**root cause**：Coder 的 P0b pre-flight "判断引导" 误导 LLM——看到 `search_in_files` 已存在，引导被解读为"功能已具备 → 无需修改"，跳过编辑。质量门"计划文件未修改"是 warning-only，导致空实现 exit 0。

**补充**：yscode test_tools.py 有 5 个预存 encoding 失败（断言英文错误消息，实际输出中文），但这不是 task52 失败的直接原因。

**修复方向**：
- yansh：P0b 引导要区分"已存在函数"vs"需要给已存在函数加参数"
- 质量门"计划文件未修改"升级为硬失败（或至少对 `files_modified==[]` 判 fail）
