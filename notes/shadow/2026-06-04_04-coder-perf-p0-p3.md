# coder 性能改进 P0-P3

日期：2026-06-04  
commit：dc51541

## 背景

task5 基准测试（干净 workspace）：780s / 2.17M tokens。opus-4.8 分析 log 发现 5 项浪费点，实施了 5 项改进。

## 改进内容

### P0a：压缩 thrashing 修复（agent.py:2404-2421）

**问题**：`_compact_messages` 估值"未降低"或"反增"时，`_compact_consecutive_over` 不自增，保护机制永远触发不了。task5 触发 5 次压缩，其中 2 次估值反增，白跑。

**修法**：`else` 分支（未降低/反增）改为 `_compact_consecutive_over += 1`；把 `>= _compact_max_consecutive` 判定上提到两分支之外，统一触发 `_compact_disabled = True`。日志改打印 `_est`（保留值）而非 `_new_est`（可能更大的反增值）。

### P0b：coder early exit 加强（agent.py:2438-2453）

**问题**：pre-flight check 提示已有但不够有力，coder 仍按 expected_edits 预算反复读大文件"确认"。

**修法**：
1. 提示层：pre-flight 改为 MANDATORY first step，明确"search 命中 → 立即 task_complete，禁止 read_file 二次确认"。
2. 代码层：`_dispatch_tool_calls` 返回后，遍历 `outs` 检测 `search_in_files` 命中（total ≥ 1），注入 user 引导消息，压迫 LLM 下一轮直接 task_complete，打印 `[P0b pre-flight]` 日志。

### P1：lint 范围收窄（linter.py:10-30，agent.py:3512）

**问题**：`ruff check .` 扫全 repo 产出 228 条错误，全部喂给 fixer LLM；fixer 只处理 6 处但要消化 2400 行 lint 输出，触发一次 65K token 预算提醒。

**修法**：`run_linter_for` 加 `files` 参数，有 files 时 `ruff check "a.py" "b.py"`；agent.py 调用处传入 `snapshot_files_modified()`，只扫改动的 `.py` 文件；无 files 时 fallback `ruff check .`。

### P2：轮次硬上限（agent.py:2366-2369，config.py:113）

**问题**：`expected_edits=60` → coder 分配约 23 轮预算，太宽松。

**修法**：`min(当前公式结果, _hard_cap)` + `max(..., min(_base_rounds, _hard_cap))` 防饿死。`coder_max_rounds_per_file` 默认 12，注册到 config.py。`expected_edits=60` 场景从 23 轮降至 12 轮，≤9 edits 的小任务保持基线 5 轮不变。

### P3：read_cache key 规范化（agent.py:1144-1172）

**问题**：cache key 精确匹配 `(filename, offset, limit, max_bytes)`，同文件不同参数读取全部 miss。task5 命中率 0/21（0%）。

**修法**：新增 `_read_cache_key` 规范化函数：`offset None/0/1 → 1`（与 `read_file` 实际行为对齐），`limit/max_bytes None → "__ALL__"` sentinel。不同 limit 值之间仍是不同 key，避免假命中。

## 验证

- opus-4.8 review：0 Major，2 Minor（日志变量 + config 键）已修复后 commit

| 指标 | 改进前 | 改进后 | 变化 |
|------|--------|--------|------|
| elapsed | 780s | 360s | -54% |
| tokens | 2.17M | 600K | -72% |

超出 opus-4.8 预估（预估省 1.2–1.5M，实际省 1.57M）。

## 关键经验

- `ruff check .` 是隐形成本大户：全仓 228 条 lint → fixer 2400 行 prompt，fix 阶段 token 的主要来源
- 压缩 thrashing 的"未降低"路径比"反增"路径更容易忽视，两者都要计入
- read_cache key 规范化必须与 `read_file` 实际语义严格对齐（`offset None/0/1` 确实等价），否则假命中
- 轮次上限 ≤12 既防膨胀又不饿死小任务（base 5 轮被 max 保护）
