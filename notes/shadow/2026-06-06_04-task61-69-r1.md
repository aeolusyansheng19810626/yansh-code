## 根因诊断（看 log）

### task65（最严重）：rename 误判为 readonly → audit + haiku
- log 证据：`"plan": []`、全程只读工具、`task_complete(success=True, "审计完成...重命名范围确认")`、`by_model` 全是 haiku。
- 根因（agent.py:356-362）：prompt 含"功能**保持不变**"，命中 `_NO_MODIFY_ZH=[...,"保持不变"]`，第 1.5 步直接 `return "readonly"`，优先于后面的写入信号检查 → 走 audit() 路径 + haiku。
- "保持不变"是重构/重命名惯用语，被当成"不要改代码"信号 → 误伤所有"重构但功能不变"类任务。

### task61：plan 轻信前提，coder 幻觉硬造
- log 证据：plan intent 直接写"在 batch_read_files() 内部引入..."，从不验证函数是否存在；coder 发现不存在仍 `append_to_file` 新建。
- 根因：缺"修改 requirement 声称'已有'的目标前先验证存在性"的约束。

### 63/66/69：测试 harness 并发脆弱（非 yansh 缺陷）
- 三批各自第 3 个几乎同时启动 → 并发峰值触发 editable install 的 `No module named main`。
- 单进程用户不会遇到；属测试脚手架问题。task66 还暴露判定漏洞（exit≠0 却判 success）。
