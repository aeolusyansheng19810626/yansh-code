## Task 21（中等）— 性能优化

**Prompt**：
```
datakit 的 find_duplicates(items) 函数在处理 10000+ 条目的列表时明显变慢。
请先用 execute_command 对当前实现做基准测试，再优化算法，
确保优化后的版本在 10000 条目时比原版快至少 10 倍。
加 2 个单测：结果正确性 / 大列表性能（用 timeit 断言执行时间 < 0.1s）。
```

**难点**：必须用 execute_command 先 benchmark，不能靠感觉（pattern 5 扩展）

## Task 22（中等）— 多 bug 同时修复

**Prompt**：
```
datakit 的 CSV 解析器有 3 个 bug：
1. 解析 "name, age" 这样逗号后有空格的 CSV 时，字段名带前导空格（如 " age" 而非 "age"）
2. 字段值中含逗号但被双引号包裹时（如 "Smith, John"）会错误拆分
3. parse_csv_line 返回的字段值保留了外层引号（"John" 而非 John）
定位并修复全部 3 个 bug，每个 bug 加 1 个单测。
```

**难点**：3 个 bug 独立但相关，需要系统排查而不是修一个就 task_complete

## Task 23（中等）— 向后兼容 API 变更

**Prompt**：
```
扩展 datakit 的 format_record(name, value) 函数：
1. 加可选 unit 参数：format_record("weight", 70, unit="kg") → "weight: 70 kg"
2. 新增 format_records(records: list[tuple]) -> str 批量格式化函数，
   records 里每项是 (name, value) 或 (name, value, unit) 元组
旧调用方式 format_record("age", 25) 必须继续工作，不能报错。
加 3 个单测：旧调用兼容 / unit 参数 / batch 函数。
```

**难点**：改完后要验证旧测试仍然全部通过，scope 纪律

## Task 24（中高）— 输入验证/边界防御

**Prompt**：
```
datakit 的 validator.py 里 validate_age、validate_email、validate_phone
目前对非法输入（None、负数、错误类型）没有防御，会抛出 TypeError 或返回错误结果。
给每个函数添加完整的输入校验：
- 类型错误 → 抛 TypeError，消息说明期望类型
- 值越界/格式错误 → 抛 ValueError，消息包含具体的非法值
- 加 6 个单测：每个函数各 2 个（类型错误 / 值错误）
```

**难点**：要覆盖每个函数的所有错误路径，不能只改一个

## Task 25（中高）— 大文件定位 bug

**Prompt**：
```
datakit 的 indexer.py（约 300 行）里 search_phrase(phrase) 函数有 bug：
搜索 "hello world" 时，如果文档里有 "hello world" 应该匹配，
但实际上会漏掉正确的匹配，或者匹配到错误的位置。
用户只知道现象，不知道具体在哪一行。
定位根因，修复，加 2 个单测：正确短语被找到 / 错误短语不被找到。
```

**难点**：需要 search_in_files / list_symbols 导航 300 行文件，找到 off-by-one
