## 改了什么

### P1 #4：JSON 解析健壮性

**1) llm_client.py：response_format 探测**

之前是硬编码"Claude 跳过 response_format"——粗糙。改为：

- `_should_skip_rf(model)`：硬规则（已知差表现 model）+ 动态黑名单（运行时 400 后加入）
- `_RF_UNSUPPORTED: set` 进程级缓存
- `_call_single_model` / `call_llm` 捕获 `_looks_like_rf_rejection(exc)`，命中后把 model 加进黑名单，自动剥掉 response_format 重试一次

**关键发现（实测）**：ICA 后端**不报 400 但会降质**——
传 `response_format={"type": "json_object"}` 给 Sonnet 4.6 时输出退化成 `{}`，
比 400 拒绝更隐蔽。所以 Claude 走的是"硬跳过"路径而不是"探测降级"路径。

笔记给后人：动态探测对未来未知后端有用；当前后端的已知坑放硬规则才不会每次踩。

**2) agent.py：`_call_with_json_retry` 包装**

```python
def _call_with_json_retry(stage, messages, parser_fn,
                          response_format=None, stream=None, ...):
    response = call_llm(...)
    ok, data, err = parser_fn(content)
    if ok: return data
    # retry 1 次：把原始内容 + 错误带回 LLM
    retry_messages = messages + [
        {"role": "assistant", "content": content},
        {"role": "user", "content": f"上一轮你的输出无法被解析为合法 JSON...错误：{err}\n前次输出：{raw}"},
    ]
    response2 = call_llm(retry_messages, ...)
    ok2, data2, _ = parser_fn(content2)
    if ok2: return data2
    # 两次都失败 → log raw + 返回降级值
    return data2
```

`_parse_plan_response` / `_parse_review_response` 拆成两层：
- `*_with_status` 返回 `(ok, data, err)` 三元组——retry 包装用
- `*_response` 旧入口委托并 log，单测向后兼容

`plan()` / `review()`（仅 `REVIEW_MODEL` 未设时）改用 retry 包装。

### P1 #5：全局状态重构（渐进式）

不动模块级变量（agent._BATCH_MODE / _PROJECT_TYPE / _CURRENT_SNAPSHOT、
tools._BATCH_MODE / _BATCH_STRICT / _AST_CACHE），新建 `state.py`：

- `Session` dataclass：字段镜像所有可变状态
- `Session.pull()`：从模块拉一份快照
- `Session.push()`：把 Session 写回模块
- `Session.reset(workspace_dir=None)`：一行清零（含 AST 缓存）
- `scoped_session(workspace_dir)` context manager：进入拍快照→reset；退出 push 快照恢复

测试现在可以 `with scoped_session(tmp_path): ...` 隔离一个用例。
后续若要把状态完全迁出去，逐文件改读写到 `current()` 即可——本次不做。

**为什么不上完整 Session class 替代模块全局**：
- agent.py / tools.py 共两份 _BATCH_MODE，集成 import 链复杂
- 一次性大爆炸重写要改 ~15 处读写 + 测试 fixture
- 渐进式：先解决"测试可隔离"这个最痛的点，未来再迁

### P1 #6：沙箱模式 opt-in

新建 `sandbox.py`（专用模块，避免污染 tools.py）：

- `SandboxConfig(enabled, backend, image, extra_args)` dataclass
- `parse_cli_arg(value)` 解析 `--sandbox docker[:image]` / `none`
- `wrap_command(cmd, ws)`：禁用时原样返回；启用时输出
  ```
  docker run --rm -i -v <abs(ws)>:/ws -w /ws <image> sh -c '<cmd>'
  ```
  用 `shlex.quote` 防注入

接入点：
- `tools.execute_command`：在 Popen 之前调一次 `sandbox.wrap_command()`，禁用时零开销
- `main.py`：加 `--sandbox` 参数；启动 banner 显示 `沙箱: off | docker:python:3.11-slim`

**只包 execute_command**：read_file / write_file 等都是受控 IO；execute_command 是
唯一"会运行任意代码"的工具。

**为什么 rw 而不是 ro 挂载**：测试常需要写中间文件；隔离的核心收益是"文件系统/进程/网络
都被命名空间隔离"，挂 ro 反而把"跑测试"这条路径砍了。后续可加子选项 `--sandbox docker:img:ro`。

## 评估

P0 三项把"功能正确"夯实，P1 三项把"工程健康"夯实：

- **P1 #4** 修了一个隐蔽 bug：之前以为 Claude 跳过 response_format 是"防御性兜底"，
  实测发现是"必须的"——ICA 接受参数但降质输出。retry 包装现在让 plan/review 在
  极端 case（schema 校验失败）下能自救一次。
- **P1 #5** 不是大重构，是"测试可隔离"的最小工程化——`scoped_session` 让单测告别
  `reload(tools)` 这种 hack。完整 Session class 留给未来。
- **P1 #6** 是 opt-in 安全：默认零行为变化、零 docker 依赖；启用一行 CLI 即可隔离。
  当前没有真正的 docker 测试因为开发机没装，需要时换 host 再补。

下一波（不在这次范围）：
- P1 #4 续做：ICA 后端何时支持 native structured output（可能新 API 版本）
- P1 #5 续做：完整迁移模块级变量到 Session 实例（一文件一文件改）
- P1 #6 续做：`--sandbox docker:img:ro` 子选项；网络隔离 `--network=none`；alternative backend（podman / firejail）
