# task53-59 根因分析

## task53（纯文档任务，success=false 误报）

**任务**：评估 audit 模式可行性，输出 markdown 文档，不写代码、不改 repo。

**结果**：`success: false`，`files_modified: ["notes/audit-to-code-readonly-feasibility.md"]`。

**两个问题**：
1. **yansh 越界改了代码**：除文档外还改了 `subagent.py`、`tools.py`、`test_tools.py`（`_err` 签名加 `tool` 参数），违反"不写代码"约束，但这些改动未进入 `files_modified`（抓取口径不一致）
2. **success=false 是误报**：new_failures 的两个 `test_subagent.py` 测试在 baseline 就已失败（mock 未生效，跑到真实 ICA 网关），但被 diff 逻辑算成"新增失败"

**根本原因**：测试套件有 flaky/mock 失效测试，baseline 捕获不完整 → 误判 success。yansh 本身也违反了只读约束。

## task56（--mode summary，success=false）

**任务**：新增 `--mode summary` 子命令，加 3 个单测。

**结果**：`success: false`，3 个新测试全挂 `ImportError: cannot import name 'get_recent_logs' from 'task_log'`。

**根本原因**：workspace 测试 import 解析到了真实 `yansh-code\task_log.py`（PYTHONPATH 污染）而非 workspace 副本，导致 `get_recent_logs` 始终找不到。Tester 误诊为 sys.path 层级问题，反而加剧污染。另：`main.py` 子命令因 Coder 5 轮工具调用上限耗尽未落地。

**两层问题**：
- 环境隔离缺陷：workspace 测试 import 路径污染
- Coder 轮次耗尽：main.py 缺失

## task59（--budget 功能，success=false）

**任务**：新增 `--budget <K>` CLI 参数，llm_client.py 追踪消耗，超出时 raise BudgetExceededError。

**结果**：`success: false`，new_failures: `test_hooks::test_run_one_hook_timeout_kills_process_tree`（flaky）。

**实现情况**：新增了 `BudgetExceededError`、`LLMClient` 类（llm_client.py）、config.py 改动、2 个 budget 单测——单测本身 PASSED。但 `main.py`（--budget CLI）和 `agent.py`（捕获退出）因 Coder 轮次耗尽未落地。

**根本原因**：
1. Coder 轮次耗尽 → 核心功能实现残缺（CLI 入口缺失）
2. flaky hook 超时测试 → 被误判为新增回归
